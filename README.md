## 二、这次改的四件事

### ① 修掉「草莓粘住不落」的 bug

**根因有两个，都在物理引擎上：**

1. **Matter.js 的「沉睡」机制**（真正的元凶）：水果在半空互相卡住、速度接近 0 时会被判定为睡着，
   睡着之后引擎**不再给它加重力**，它就会永远挂在半空不再下落 —— 看起来就是「草莓粘在别的水果上掉不下来」。
   → 已关闭 `enableSleeping`（`js/config.js` 的 `PHYSICS.enableSleeping: false`）。
2. **摩擦系数偏大**：圆水果之间应该互相打滑滚开，原来的摩擦让它们像粘在一起。
   → 水果之间摩擦 `0.3 → 0.1`、静摩擦 `0.6 → 0.16`（墙壁保持 0.3，不然靠墙会滑）。

**量化验证**（`tests/logic.test.mjs`）：
- 半空放一颗草莓 → 一定会掉下去，不再停在空中；
- 30 颗水果乱丢后逐颗检查：**没有任何一颗水果悬空且不接触任何东西**；
- 静置 30 秒：果堆最大位移 **0.05px**、最大瞬时速度 0.037、平均速度 0 —— 既不下坠也不抖、也不自己滑动。
- 关掉沉睡后仍然完全不抖（迭代次数 12），所以这个改动不牺牲稳定性。

> 请重点试一下手感：现在水果更容易滚进缝隙、果堆更「松散自然」。如果觉得太滑，把 `PHYSICS.fruit.friction` 调到 0.15~0.2 即可。

### ② 连击加分

- **1 秒内连续合成**算连击；倍率 = `1 + (连击数-1) × 0.3`，**最高 ×2.5**（封顶约 6 连）。
- 加成取「倍率加成」和「每连击 +1 分」里更大的那个，所以小水果连击也有收益：
  - 连击 2 合成草莓（基础 1 分）→ **2 分**
  - 连击 2 合成西瓜（基础 55 分）→ **72 分**
  - 连击 6 及以上 → 固定按 ×2.5 算
- 表现：记分板下方出现**连击条**（连击数 + 当前倍率 + 剩余时间条），画布上会飘出金色的「连击 ×N」，
  粒子、屏幕震动和合成音的音高都会随连击提升；窗口超时后连击自动归零。
- 结算卡片新增「最高连击」。规则都在 `js/config.js` 的 `RULES.combo`。

### ③ 排行榜：全球共享（不需要自己的服务器）+ 两个榜

**在线地址：https://vanilla-icewagtail.github.io/merge-watermelon/** —— 任何人打开这个链接，
成绩都会进同一张榜，和你本机打开 `index.html` 看到的是同一张。

原理（`index.html` 是纯静态页面，自己没有后端）：**整张榜单就是一份 JSON 文档，存在第三方免费 KV 服务上**
（`js/config.js` 里的 `BOARD_SYNC.textdb.endpoint`），全世界玩家的浏览器读写同一份。

- **实时榜**：最近 20 次提交 —— 打开榜单面板就去拉最新（20 秒节流），所以看起来是实时的；
- **总榜**：历史前 100 —— 每 30 分钟自动刷新一次，也可以点「同步」手动拉；
- 自己刚打完那一局先以「**待确认**」显示，写完再读一次确认真的上了远端才算成功；
- **待上传队列**：提交失败就存本机，联网后自动补传，不丢成绩；
- **自愈**：每个客户端本地都缓存一份，读到远端时合并取优 —— 有人把榜刷没了、或者并发写丢了一次，
  任何一个还留着缓存的客户端下次读写就会把它修回来（代价：远端没法被单方面清空，想重置就换个 key）；
- **没有个人排行表**：文档里只有 `top` 和 `live` 两块，每局成绩只进榜，不给玩家攒个人历史（有测试盯着）。

想换成自建服务器（有服务端校验、能防乱写）：把 `js/config.js` 里的 `BOARD_SYNC.provider` 改成 `'rest'`，
用仓库里的 `server.cjs`（静态服务 + `/api/scores`）：局域网用 `启动共享榜.cmd`，
公网就把它丢到一台有公网地址的机器/容器上（只有 Node 内置模块依赖，`node server.cjs --port 8080`）。

**两个必须说清楚的风险（做法 C 的固有代价）**：

1. 第三方 KV **没有服务端校验**，谁都能改那张榜（客户端代码里的凭据等于公开），榜上成绩只能当娱乐；
2. 榜单数据存在别人的服务器上，你的昵称和分数会发过去（和访问任何网站一样，对方能看到 IP）。

（本机调试时可以用 `?board=local` 强制只记本机、`?board=rest` 走自建服务器。）

服务端接口（`server.cjs`，已带 CORS，方便以后放公网）：

```
GET  /api/health   → {ok, service, updatedAt, count}
GET  /api/scores   → {ok, updatedAt, count, entries:[...]}          # 前 100 名，按分数/等级/时间排序
POST /api/scores   → {ok, accepted, duplicated, rejected, rank, updatedAt, count, entries}
                      body 可以是单条成绩，也可以是 {entries:[...]}（最多 50 条）
                      id 重复只记一次；坏 JSON → 400；超过 256KB → 413
```

顺带修掉一个**并发丢成绩**的真 bug：3 个人同时提交时，服务端「读榜单→合并→写回」会互相覆盖，
最后只剩 1 条（真实浏览器里复现过）。现在整段读改写串行化，8 条并发提交一条不丢，
`tests/server.test.mjs` 里有回归测试盯着。

### ④ 难度 1~10 级，默认从「4 点」上调到「5 点」

之前没有难度系统，这次按你说的做了 10 级，并把**默认定在你原来的 4 级之上加一档 = Lv.5「熟练」**：

## 五、图片流程（还是原来的约定）
